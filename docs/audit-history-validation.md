# 审计历史验收记录

日期：2026-09-09。验收覆盖两级接口、分页状态层、界面接入及边界/规模回归四个阶段。

## 已覆盖的行为

- 会话分组按 20 个、组内记录按 50 条独立分页；旧会话标题直接关联，Direct/MCP 范围不串组。
- 服务端字面搜索覆盖未加载记录；分页保持纳秒精度与固定时间上界。
- 主机、开始时间、结束时间可独立或组合筛选；分组和组内记录使用相同范围，反向时间范围不会发出前端请求。
- 新增 150 条记录后重新校准连续的已加载窗口；重连不退回第一页。
- 搜索、删除、隐藏与迟到响应竞争；HTTP/WebSocket 删除通知乱序去重。
- 少量完整结果默认展开，手动收起不被加载更多、刷新、删除或切页覆盖。
- 并发外层翻页只补载一次组内记录；旧补载不能进入新搜索的窗口。
- 失败页重试保留游标；移动到后续页的已有分组更新原记录而非留下重复或旧计数。
- 详情懒加载、摘要变更失效、收起/隐藏/卸载取消、旧响应隔离及显式重试。
- 会话改名、删除后通过 WebSocket 通知重新读取已提交数据，不新增用户操作审计记录。
- 既有 Agent/MCP 历史查询与鉴权/可信会话隔离保持不变。

## 规模测试

本机 Windows、测试临时数据库。SQL 各场景读取 5 次，以下为近似中位耗时，不代表生产环境 SLA。

| 场景 | 结果 |
| --- | --- |
| 10 万条运行，首屏 20 个分组 | 约 61 ms |
| 其中一个会话 5 万条运行，首屏 50 条 | 小于 1 ms |
| 同时间戳、接近末尾的深页 50 条 | 优化前约 11.5 ms，优化后约 0.5 ms |
| 搜索一条未加载旧记录，含分组与组内查询 | 约 94 ms |
| 3 万条运行，主机与时间范围命中约 1% | 优化前约 35 ms，优化后小于 1 ms |
| 3 万条运行，仅时间范围命中约 1% | 优化前约 25 ms，优化后约 0.5–2.5 ms |
| 前端加载 1000 条，突发 1000 个审计事件 | 合并为一次校准：1 次分组请求、20 次记录请求；2 次分组通知、3 次记录通知 |

查询计划断言验证深页、时间范围及主机时间范围均使用对应表达式索引。合并排序最多处理两页候选记录；旧数据库只补建索引，不迁移时间戳。分组聚合和字面子串搜索仍随匹配范围增长，未引入汇总缓存或全文索引。

前端状态测试验证未改变的记录保持对象引用、空闲无轮询与残留事件定时器。通知次数不是 React 提交次数或 GPU 帧率测量。
